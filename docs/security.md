# MXReady 安全模型

本文描述 MVP 已实现的边界，不构成对公开互联网多租户 SaaS 的完整安全审计。当前推荐在本地、比赛演示环境或由单一维护者控制的服务器部署。

## 信任边界

| 数据/组件 | 信任级别 | 处理方式 |
| --- | --- | --- |
| 公开仓库 URL、ref、源码 | 不可信 | 主机白名单、受限 Git、只读索引、永不执行 |
| YAML 规则集 | 受信任项目代码 | 随版本发布、严格模型校验、代码评审 |
| 验证 ZIP | 受信任生成物 | 用户下载后必须人工审阅 |
| 项目验证命令 | 高风险 | 只在用户控制主机、人工 `yes`、`shell=False` |
| 上传的 result.json | 不可信 | 1 MiB 上限、严格契约、提交绑定 |
| 报告文本与证据 | 不可信输出 | React 转义、Markdown/HTML 转义、固定 SVG 文本 |

## 仓库获取

公开 Web API 只接受：

- `https://github.com/<owner>/<repo>`
- `https://gitee.com/<owner>/<repo>`

拒绝用户名、密码、自定义端口、查询参数、fragment、本地路径、SSH、`file://` 和其他主机。ref 经过独立格式校验。

Git 环境设置：

- `GIT_TERMINAL_PROMPT=0`
- 空 credential helper
- `GIT_LFS_SKIP_SMUDGE=1`
- `--no-tags`
- 浅克隆
- 不初始化子模块

硬限制：

| 限制 | 值 |
| --- | ---: |
| Git 操作超时 | 60 秒 |
| 克隆后仓库大小 | 50 MiB（52,428,800 字节） |
| 仓库文件数 | 10,000 |
| 可索引候选文件数 | 10,000 |
| 单个索引文本文件 | 1 MiB（1,048,576 字节） |

遍历不跟随符号链接，跳过 `.git`、构建目录、虚拟环境、缓存、`node_modules`、`vendor` 等目录。只读取明确后缀或文件名的 UTF-8/GB18030 文本。

本地 `mxready-scan-public` 证据命令在 GitHub 的 Git 传输超时或内部失败时提供归档后备路径。它先通过 GitHub API 将 ref 解析为 40 位提交，再从 `codeload.github.com` 获取该提交。该路径：

- 只适用于已经通过 URL 白名单的 GitHub 身份；
- API 元数据最多 1 MiB，压缩下载最多 50 MiB；
- 展开后仍最多 50 MiB、10,000 个普通文件；
- 拒绝绝对路径、`..`、控制字符、加密条目、特殊文件和大小声明矛盾；
- 跳过符号链接，并拒绝大小写不敏感的重复文件路径；
- 只写入本次命令创建的临时目录，分析完成后自动清理。

公开 Web API 不启用这一后备路径，仍只使用上面的受限 Git 流程。

## 不执行保证

Web 扫描路径只使用文件元数据、字节读取、Python `ast`、`tomllib`、正则和 YAML 规则。它不会：

- 导入仓库 Python 模块；
- 运行 `setup.py`、构建后端、CMake 或 shell 脚本；
- 安装依赖；
- 编译 CUDA/C++；
- 加载仓库动态库；
- 运行测试。

本地 `mxready-scan` 也调用同一只读分析器，但本地路径本身属于开发者信任范围；它不会通过公开 API 暴露。

## 远程 runner

runner 在用户控制的沐曦主机执行，Web 服务只生成和接收文件。安全契约包括参数数组、`shell=False`、命令验证、1–600 秒超时、人工批准项目命令、输出截断和脱敏。runner 不使用 `sudo`、不调用包管理器、不修改驱动。

自动脱敏只是最后一道保护，上传前仍必须人工查看 `result.json`。不要上传主机名、内网地址、用户名、令牌、模型数据或私有源码片段。

## Web 与输出

- Pydantic 对外模型设置 `extra="forbid"`；
- 验证上传最大 1 MiB，并校验扫描 ID、精确提交、关键 GPU 检查与 30 天时效；
- 报告下载文件名经过字符清洗；
- Markdown 对控制字符和 HTML 敏感文本转义；
- SVG 只呈现固定状态，不插入仓库证据；
- React 默认转义文本，外链使用 `rel="noreferrer"`；
- Vite 指纹资产使用 immutable 缓存，SPA HTML 使用 `no-store`；
- SPA fallback 明确排除 `/api`，未知 API 不返回 HTML。

## 部署假设与建议

MVP 没有认证、配额、队列隔离、分布式任务系统或公网滥用防护。不要直接作为匿名公共 SaaS 暴露。若部署到共享网络，至少应在反向代理层增加：

- 访问控制与 TLS；
- 请求体和并发限制；
- 每来源速率限制；
- 出站网络策略；
- 独立低权限系统用户；
- 数据目录备份与定期清理；
- 日志脱敏和监控。

不要让服务进程访问云元数据地址、内部 Git 凭据或生产密钥。

## 漏洞披露

不要在公开 Issue 中发布可直接利用的细节、密钥、私有地址或他人数据。

1. 优先使用代码托管平台的私密 “Report a vulnerability” 通道（若仓库已启用）；
2. 若没有私密通道，只创建一个不含技术细节的 Issue，请维护者提供安全联系方式；
3. 提供受影响版本、最小复现、影响范围和建议缓解方式；
4. 在修复和发布说明完成前，不公开利用代码。

安全问题会优先处理；普通规则误报和文档问题可以直接提交公开 Issue。

# MXReady 安全模型

本文描述 MVP 已实现的边界，不构成对公开互联网多租户 SaaS 的完整安全审计。当前推荐在本地、比赛演示环境或由单一维护者控制的服务器部署。

## 信任边界

| 数据/组件 | 信任级别 | 处理方式 |
| --- | --- | --- |
| 公开仓库 URL、ref、源码 | 不可信 | 主机白名单、受限 Git、只读索引、永不执行 |
| YAML 规则集 | 受信任项目代码 | 随版本发布、严格模型校验、代码评审 |
| 验证 ZIP | 受信任生成物 | 用户下载后必须人工审阅 |
| 项目验证命令 | 高风险 | 只在用户控制主机、人工 `yes`、`shell=False` |
| 上传的 result.json | 不可信 | 1 MiB 上限、严格契约、提交绑定 |
| 报告文本与证据 | 不可信输出 | React 转义、Markdown/HTML 转义、固定 SVG 文本 |

## 仓库获取

公开 Web API 只接受：

- `https://github.com/<owner>/<repo>`
- `https://gitee.com/<owner>/<repo>`

拒绝用户名、密码、自定义端口、查询参数、fragment、本地路径、SSH、`file://` 和其他主机。ref 经过独立格式校验。

Git 环境设置：

- `GIT_TERMINAL_PROMPT=0`
- 空 credential helper
- `GIT_LFS_SKIP_SMUDGE=1`
- `--no-tags`
- 浅克隆
- 不初始化子模块

硬限制：

| 限制 | 值 |
| --- | ---: |
| Git 操作超时 | 60 秒 |
| 克隆后仓库大小 | 50 MiB（52,428,800 字节） |
| 仓库文件数 | 10,000 |
| 可索引候选文件数 | 10,000 |
| 单个索引文本文件 | 1 MiB（1,048,576 字节） |

Git 工作树大小在克隆完成后校验，因此 50 MiB 是扫描准入上限，不是网络传输的硬字节配额。公网部署还应限制临时目录磁盘空间并监控异常下载；Git 操作始终受 60 秒墙钟超时约束。归档后备路径则在下载和展开阶段都执行独立的字节与条目上限。

遍历不跟随符号链接，跳过 `.git`、构建目录、虚拟环境、缓存、`node_modules`、`vendor` 等目录。只读取明确后缀或文件名的 UTF-8/GB18030 文本。

本地 `mxready-scan-public` 证据命令在 GitHub 的 Git 传输超时或内部失败时提供归档后备路径。它先通过 GitHub API 将 ref 解析为 40 位提交，再从 `codeload.github.com` 获取该提交。该路径：

- 只适用于已经通过 URL 白名单的 GitHub 身份；
- API 元数据最多 1 MiB，压缩下载最多 50 MiB；
- API 元数据请求和归档下载各自使用 60 秒总墙钟时限，而不是为每次 socket 读取重新计时；
- 在创建 `ZipFile` 对象前先验证中央目录，目录、符号链接和普通文件都计入 10,000 条归档成员上限；
- 展开的普通文件内容合计仍最多 50 MiB；
- 拒绝绝对路径、`..`、控制字符、加密条目、特殊文件和大小声明矛盾；
- 跳过符号链接，并拒绝大小写不敏感的重复文件路径；
- 先写入同级 staging 目录，成功后原子移动；失败时清理本次创建的部分结果。

公开 Web API 不启用这一后备路径，仍只使用上面的受限 Git 流程。

## 不执行保证

规则正则在标准库启动的独立匹配进程中执行，该进程只接收受信规则表达式与源码文本，
不导入或执行被扫描仓库。规则评估的默认 30 秒墙钟预算包括进程启动和匹配；
单次正则在首个命中前阻塞时也能被父进程终止，超时后不输出部分通过结果。
索引、事实提取和 Git 获取仍遵循各自现有流程，这不是整次扫描的统一总时限。

Web 扫描路径只使用文件元数据、字节读取、Python `ast`、`tomllib`、正则和 YAML 规则。它不会：

- 导入仓库 Python 模块；
- 运行 `setup.py`、构建后端、CMake 或 shell 脚本；
- 安装依赖；
- 编译 CUDA/C++；
- 加载仓库动态库；
- 运行测试。

本地 `mxready-scan` 也调用同一只读分析器，但本地路径本身属于开发者信任范围；它不会通过公开 API 暴露。

## BYOK 代码工作区（可选）

`/code` 与 `mxready-agent` 是本地开发助手，不属于 Web 扫描服务或 runner 信任边界的一部分。
Web 与 runner 不导入 `mxready.agent`；启用该工作区不会让 Web 获得写文件或执行命令的能力，
也不会改变上面的“不执行被扫描仓库代码”保证。

**密钥与配置**

- API Key 只通过弹窗输入，优先写入操作系统凭据库；
- 凭据库不可用时写入 `agent-dir/secrets.vault`：`scrypt(n=2^14, r=8, p=1)` 派生密钥，
  AES-GCM 加密，16 字节 salt 与 12 字节 nonce，原子替换文件；
- 主密码仅保存在当前进程内存，不写盘、不进入命令行；
- `agent-dir/config.json` 只保存服务名、协议、base URL、模型、`key_ref` 与
  Key 的 12 位 SHA-256 指纹，绝不保存 Key 明文；
- `MXREADY_AGENT_API_KEY` 仅为当前进程提供临时 Key，优先级最高且不落盘；
- Key 不进入命令行参数、输入历史、界面回显、错误消息或审计日志。

**模型网络请求**

- 仅接受 HTTPS；只有 `localhost`、`127.0.0.1`、`[::1]` 等回环地址允许 HTTP；
- 拒绝 URL 中的账号密码、查询参数、fragment、反斜杠和控制字符；
- TLS 校验开启，忽略代理环境变量，不跟随重定向；
- 连接超时 10 秒、读取超时 180 秒，响应体最多 20 MiB；请求开始后不自动重试；
- 模型 API 是该工作区唯一的网络出口，不下载或执行远端代码。

**工具与审批**

- 默认只读：读取/列出/搜索工作区文件，查询当前扫描报告；
- `/elevate` 后增加写入、补丁与命令执行，但每次调用都弹出独立确认；
  用户拒绝、未提权或不提供确认回调时一律拒绝并记录审计；
- 路径解析拒绝 `..`、绝对路径逃逸、`~`、符号链接、控制字符与敏感名称；
- 命令使用参数数组、`shell=False`，拒绝 shell 宿主、`sudo`/`env`/`xargs` 等包装器；
- 每次命令独立超时 1–600 秒，超时或取消时终止进程树；
- 采集阶段 stdout/stderr 各保留 16 KiB、总输出 40 KiB，持续排空避免无限缓存；
- 子进程环境剥离 Key、token、secret、password、credential、authorization 等变量；
- 一次对话最多 8 轮工具调用、20 万 token 预算，单条消息最多 32 KiB。

**审计**

`agent-dir/audit.jsonl` 记录时间、会话、工具、决定与截断后的目标/结果，不记录文件内容、
模型消息或密钥；常见 `key=value`、Bearer 与 `sk-` 形式会脱敏。文件超过 5 MiB 轮转，
最多保留 3 份。审计是追加记录，不会抑制静态扫描发现或改变验证结论。

**部署建议**

`agent-dir` 默认位于用户数据目录，与安装目录、Web 数据库和扫描报告分开；不要把该目录、
`secrets.vault` 或 `config.json` 提交到版本库。提权执行命令仍是高风险能力，
只应在用户信任的工作区中使用，并在执行前检查弹窗中的命令、工作目录与超时。

## 远程 runner

Windows 10/11 的命令由标准库 Job Object 监督进程启动；监督进程先加入作业，
再启动已人工批准的原始参数数组，后代进程继承该作业。超时终止监督进程时，
作业的 kill-on-close 负责终止仍在运行的后代。无法建立作业时明确失败，不降级为无监督执行。
父进程等待、后代结束和输出排空共享命令截止时间；runner 与验证 ZIP 仍不依赖第三方库。
机制依据：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

runner 在用户控制的沐曦主机执行，Web 服务只生成和接收文件。安全契约包括参数数组、`shell=False`、命令验证、1–600 秒超时、人工批准项目命令、输出截断和脱敏。runner 不使用 `sudo`、不调用包管理器、不修改驱动。

清单中的环境检查必须使用 runner 固定契约中的 ID 和完整参数数组，超时可缩短但不能超过该检查的默认上限；
自定义检查应放入 `project_commands`，通过 `run` 人工批准后执行。`inspect` 仅执行固定环境检查。

每条输出流在采集阶段最多保留 16 KiB，并持续排空多余内容，避免在结果截断前无限缓存日志。
命令结束后才进行脱敏与 UTF-8 字节截断；超时路径保留有限的部分输出，并尝试终止命令进程树。

自动脱敏只是最后一道保护，上传前仍必须人工查看 `result.json`。不要上传主机名、内网地址、用户名、令牌、模型数据或私有源码片段。

## Web 与输出

- Pydantic 对外模型设置 `extra="forbid"`；
- 验证上传最大 1 MiB，并校验扫描 ID、精确提交、关键 GPU 检查与 30 天时效；
- 读取报告、徽章和下载内容时重新推导有效期；已经下载的离线文件不会自动更新；
- 验证详情读取时再次对日志脱敏并限长，不公开命令参数；查询必须同时匹配扫描 ID 与验证记录 ID；
- 人工清单仅允许更新报告内已有规则，使用严格布尔值和参数绑定；开启限流时共享写请求额度，不改变静态或硬件验证结论；
- 报告下载文件名经过字符清洗；
- Markdown 对控制字符和 HTML 敏感文本转义；
- SVG 只呈现固定状态，不插入仓库证据；
- React 默认转义文本，外链使用 `rel="noreferrer"`；
- Vite 指纹资产使用 immutable 缓存，SPA HTML 使用 `no-store`；
- SPA fallback 明确排除 `/api`，未知 API 不返回 HTML。

## 部署假设与建议

扫描历史、验证历史和人工进度属于整个服务实例，所有获准访问实例的用户共享读写权限。
新增历史列表不能作为个人工作区或多租户数据隔离；验证输出仍需上传者人工审阅。

MVP 没有认证、配额、队列隔离、分布式任务系统或公网滥用防护。不要直接作为匿名公共 SaaS 暴露。若部署到共享网络，至少应在反向代理层增加：

- 访问控制与 TLS；
- 按实际接收字节数执行的请求体限制，以及 SQLite 写事务内原子执行的并发扫描限制；
- 每来源速率限制；
- 出站网络策略；
- 独立低权限系统用户；
- 数据目录备份与定期清理；
- 日志脱敏和监控。

不要让服务进程访问云元数据地址、内部 Git 凭据或生产密钥。

## 漏洞披露

不要在公开 Issue 中发布可直接利用的细节、密钥、私有地址或他人数据。

1. 优先使用代码托管平台的私密 “Report a vulnerability” 通道（若仓库已启用）；
2. 若没有私密通道，只创建一个不含技术细节的 Issue，请维护者提供安全联系方式；
3. 提供受影响版本、最小复现、影响范围和建议缓解方式；
4. 在修复和发布说明完成前，不公开利用代码。

安全问题会优先处理；普通规则误报和文档问题可以直接提交公开 Issue。

人工复核接口只接受当前报告中已有的规则/文件组合，按扫描绑定且追加历史；原因限制为
1000 字符，写入使用参数绑定、请求体限制和共享写请求限流。原因作为普通文本显示，
不执行其中内容。复核记录不抑制扫描发现，也不改变静态、验证或 CI 策略结果。
Web 批量继续逐项使用同一个扫描准入限制；不以批量入口绕过克隆、SSRF 或任务租约约束。
提交不确定时不自动重试 POST，避免重复任务。基线 CI 只应读取已审核来源的报告。

# 修复后的增量功能建议

本文为 2026-11-16 源码复核后的建议，尚未实现这些新功能。现有历史查询、批量扫描、
追加复核、报告对比、迁移仪表盘、SARIF/HTML 导出和 MCP 五个工具已经存在。
本轮 1.0.2 候选修复执行边界、来源标记与终端输出，尚未上传 PyPI。
更完整的背景见 [既有开发计划](development-plan-2026-11.md)。

建议按独立入口、可选字段和现有服务方法逐项交付；每项先补回归，不在新增功能中改变规则、
扫描准入、静态/硬件结论、任务租约或人工批准要求。

| 顺序 | 功能 | 使用价值 | 与现有能力的关系 |
| --- | --- | --- | --- |
| 1 | `mxready doctor` 本机诊断 | 一次解释 Python/Git、命令路径、包版本、规则/schema/网页资源和数据目录状态，减少 Windows 安装排障成本 | 新增只读 CLI；不启动扫描、不执行项目/GPU 命令、不自动改配置；支持脱敏 JSON 导出 |
| 2 | 备份与清理预览入口 | 升级前生成可校验的数据库备份，清楚查看清理会影响哪些终态扫描 | 复用 SQLiteStore 已有 backup/prune 方法；新增 CLI 与 dry-run，不更改默认保留策略；保护活跃任务，拒绝覆盖已有备份 |
| 3 | 从发现卡片直接进入复核 | 大报告筛选后，可直接复核当前发现，避免在全报告下拉框重新定位 | 复用现有追加复核 API，绑定 scan/rule/path；不隐藏 finding、不修改静态状态、验证状态或 CI 策略 |
| 4 | 批量提交的显式幂等恢复 | 请求超时、刷新或响应丢失后，找回同一次提交而不创建重复任务 | 为现有提交增加可选幂等键与原子映射；保留并发上限和“不自动重试不确定 POST”的行为；不把幂等键当成身份凭证 |
| 5 | 构建产物与验证来源关联 | 在已有本地输入摘要之外，知道 GPU 实际导入/测试的是哪个构建产物 | 增加可选补丁/二进制摘要与导入模块来源；只由用户控制的 runner 采集，Web 仍不执行项目代码；旧结果缺字段时明确未知 |

前两项适合先做：有明确的独立入口，可以复用已有方法，对扫描业务的影响较小。
随后改善复核操作，再处理涉及持久化及并发语义的幂等提交。第五项应结合实际沐曦设备复验，
不能将摘要或干净工作区标记描述为可信硬件认证。

各项的最小验收边界：

- 诊断命令应区分包损坏、Git 缺失、PATH 与资源缺失；输出不得携带令牌和完整敏感路径。
- 备份使用 SQLite 在线备份 API；恢复先在独立目录校验，清理预览与执行采用同一筛选条件。
- 复核入口覆盖换页、筛选、切换扫描、保存失败保留输入和键盘/320px 窄屏行为。
- 幂等提交覆盖并发同键、同键不同请求、响应丢失、键过期与扫描限额，保持失败关闭。
- 构建关联分别记录源码、补丁、构建产物与实际导入模块，不混同环境检查、项目测试和性能结果。

另外，扩大真实片段语料仍值得继续投入：现有小规模已标注集合不能推导总体误报率。
先为重点 blocker 规则补充固定提交的相似正反例，再以复现驱动规则调整；不优先增加规则数量。

1.0.2 候选通过本机测试，也仍需在 Linux/macOS、真实旧数据库和目标硬件上完成各自验收。
发布到 PyPI 后，还应对下载到的实际 wheel 核对版本、摘要、`--version`、重复扫描保护与服务启动。

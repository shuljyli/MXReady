# 前端功能补全方案（含 MCP 接入展示）

日期：2026-10-31

状态：FE-01～FE-09（P0/P1）已实施并验证；2026-11-02 继续补齐历史、验证详情、人工清单和报告对比。第 1～10 节保留最初方案的核对基线，第 11 节记录第一轮结果，第 12 节记录本次优化；旧方案中的“未实现”描述不代表当前状态。

## 1. 要补什么

优先补齐 **MCP 接入中心、完整规则浏览、报告中被遗漏的信息**，再完善报告检索、任务定位、验证说明和服务信息。

当前后端的大部分 HTTP 操作已经接入前端，主要问题是接口返回的信息没有完整展示，以及 CLI/MCP 能力在网页中无法被发现。另有部分功能虽然有内部存储，但没有公开查询或写入接口，不能仅靠前端补齐。

本文将开发范围分为：

- **P0：本轮应补**，包括用户明确要求体现的 MCP，以及已经存在的数据遗漏和错误版本展示。
- **P1：接着补**，利用现有接口完善查找、分享和使用引导。
- **后续扩展：需要新增后端能力**，单独说明依赖，不计入纯前端补全的交付承诺。

本方案承接 [前端重设计记录](frontend-redesign.md)，继续采用现有工作台样式。新增导航和复制操作是本轮功能扩展，替代旧设计中“单一工作区、不新增复制按钮”的范围约定。

## 4. MCP 必须在前端中明确体现（FE-01）

### 4.1 页面入口和作用

侧栏新增 **“MCP 接入”**，与“源码体检”“规则库”并列；首页增加简短入口“让编码 Agent 使用 MXReady”，报告页增加“交给 Agent 继续分析”。移动端也必须能找到这些入口。

MCP 首次出现时解释为 **模型上下文协议（Model Context Protocol）**：让支持该协议的编码 Agent 调用 MXReady，取得有规则、文件、行号和证据的迁移分析结果。

接入页应包含以下内容：

| 区域 | 用户能看到和执行的操作 |
| --- | --- |
| 能力介绍 | 支持扫描公开仓库、读取报告、列出规则和解释规则；说明静态结果与真机结果分开 |
| 安装步骤 | Python 3.11+、Git、独立环境、可选 `mcp` 依赖；复制安装命令 |
| 客户端配置 | Python 可执行文件绝对路径、数据目录等配置项；生成、复制 stdio 配置示例 |
| 工具目录 | 展示 4 个工具、参数、默认值和调用示例 |
| 报告交接 | 复制当前 `scan_id`、提交、报告地址及 `get_report` 参数；复制单条 `explain_rule` 参数 |
| 排查说明 | 解释依赖未安装、Python 路径不对、数据目录不一致、报告尚未完成与结果截断 |

### 4.2 必须准确展示的工具

| 工具 | 已实现参数及默认值 | 前端应解释的行为 |
| --- | --- | --- |
| `scan_repository` | 必填 `repo_url`；`ref=null`；`timeout_seconds=300`；`max_findings=20` | 扫描公开仓库并等待结果；超时限制为 30–1800 秒，返回发现数限制为 1–500 |
| `get_report` | 必填 `scan_id`；`max_findings=50` | 读取同一数据库里已完成的报告，返回发现数限制为 1–500 |
| `list_rules` | `category=null`；`severity=null` | 分类和级别可选，过滤不区分大小写；级别为 `blocker`/`warning`/`info` |
| `explain_rule` | 必填 `rule_id` | 精确匹配规则 ID，返回规则依据、建议、适用文件和参考资料 |

`scan_repository` 和 `get_report` 的发现按严重级别、路径、起始行排序，返回 `returned_findings`、`total_findings`、`findings_truncated`。接入说明必须提醒：Agent 收到的默认结果可能只是部分发现，不能把返回条数当作完整报告总数。

扫描等待超时会返回 `SCAN_TIMEOUT` 和扫描 ID，不代表服务端任务已被取消。后续可用扫描 ID 再查报告；未完成时会返回 `SCAN_NOT_COMPLETED`。

### 4.3 安装与配置示例

源码安装示例必须标注“在源码根目录、已激活目标 Python 环境后执行”：

```bash
python -m pip install -e ".[mcp]"
```

客户端启动命令展示 `mxready-mcp`，同时提供更明确的等价方式：**目标 Python 的绝对路径**配合参数 `-m mxready.mcp.server`，避免客户端找错 Python 环境。

以下是拟在页面生成的 Windows 示例，只适用于采用 `mcpServers` 格式的客户端；路径须由用户填写，其他客户端按其实际配置格式转换：

```json
{
  "mcpServers": {
    "mxready": {
      "command": "C:\\path\\to\\python-env\\Scripts\\python.exe",
      "args": ["-m", "mxready.mcp.server"],
      "env": {
        "MXREADY_DATA_DIR": "C:\\path\\to\\mxready-data",
        "MXREADY_TEMP_DIR": "C:\\path\\to\\mxready-data\\tmp"
      }
    }
  }
}
```

页面还应提供 Linux/macOS 路径示例。配置必须用结构化对象和 `JSON.stringify` 生成，正确处理空格、引号和 Windows 反斜杠。复制成功与失败均显示反馈；剪贴板不可用时保留可手动选中的文本。网页不替用户执行安装命令或修改客户端配置文件。

### 4.4 Web 与 MCP 的数据衔接

MCP 自己使用 `Settings.from_env()` 初始化扫描服务和 SQLite，不是对当前网页 HTTP 服务的远程转发。要互相读取报告，Web 与 MCP 必须运行在能访问**同一个本地 SQLite 数据目录**的环境，并使用一致的规则与相关配置。

尤其要提示：`mxready-serve` 默认选择系统用户数据目录，而 MCP 默认读取工作目录下的 `data/`。二者未显式统一时，即使都能启动，也可能查不到对方的扫描 ID。配置界面不能根据浏览器 URL 猜测后端磁盘路径，须让用户填写实际目录；远程部署时，本机 MCP 不能靠填写远程目录字符串共享数据库。

报告页“交给 Agent”复制的内容应带上扫描 ID、完整提交、Web 报告链接、规则/工具版本，并附以下调用参数示例。下面是**工具名与参数说明**，不是可直接发送给所有客户端的 MCP 协议报文：

```json
{
  "tool": "get_report",
  "arguments": {
    "scan_id": "00000000-0000-0000-0000-000000000001",
    "max_findings": 50
  }
}
```

实际复制时替换为当前报告 ID。未共享数据目录时，提示 Agent 使用 `scan_repository` 对同一仓库的**完整提交**重新扫描，避免默认分支变化导致分析对象不同。

### 4.5 目前不能显示的状态

现有实现采用 stdio，未提供 MCP HTTP/SSE 路由、安装状态接口或客户端连接状态接口。因此基础版前端应显示“stdio 接入方式”和配置说明，不能显示未经检测的“已连接”“MCP 已安装”或“一键远程连接成功”。

`/api/health` 只能说明 Web 服务健康，不能证明 MCP 依赖已安装或客户端已连接。若以后需要真实探测，必须增加有明确检测范围的后端契约；“依赖已安装”和“客户端已连接”仍须区分。

依据：[server.py](../src/mxready/mcp/server.py)、[Settings](../src/mxready/config.py)、[Web 启动器](../src/mxready/cli/serve.py)、[可选依赖与命令入口](../pyproject.toml)、[MCP 回归用例](../tests/backend/test_mcp_server.py)。

## 5. 规则库与动态版本（FE-02）

新增“规则库”页面，复用 `GET /api/rules` 的完整返回值，不需要新增规则查询 HTTP 接口。

- 页头显示接口的 `version`、实际规则数，以及存在时的 `extra_version`。加载失败时显示未知/重试状态，不回退到写死的 v1。
- 规则列表展示 ID、标题、分类、默认严重级别、规则版本；支持标题/ID 搜索、分类与级别筛选。
- 详情展示 `message`、`recommendation`、`file_globs`、`references`、`confidence` 和可选 `updated`。匹配模式 `patterns` 放在技术详情中。
- `confidence` 用“有资料依据 / 需人工复核”等文字解释，不能转换成准确率或兼容率。
- 报告发现中的规则 ID 可进入规则详情，并支持复制 `explain_rule` 参数。

需要区分**当前规则库**与**历史报告**：规则库的默认级别不一定等于报告发现的最终级别。路径上下文、文档字符串和工具链画像可能影响结果；当前规则版本也可能已经变化。报告继续以自身的 `severity`、`rule_version`、消息和证据为准，不能用最新规则覆盖历史结论；版本不一致时明确提示。

当前 `frontend/src/api/types.ts` 把 `RuleCatalog.rules` 缩减为 `{ id }[]`，且缺少 `extra_version`。实施时建议将 `RuleCatalog` 加入 [契约生成脚本](../scripts/generate_contracts.py) 的 TypeScript 模型集合，连同 `RuleDefinition`/`RulePattern` 一起生成，移除重复手写的最小类型。此项不改变 HTTP 响应结构。

## 6. 报告缺失信息与关联操作（FE-03、FE-04、FE-06）

### 6.1 优先复核文件

报告摘要后新增“优先复核文件”，按后端 `summary.top_blockers` 的顺序展示；点击文件可筛选或定位该文件的发现。

该字段优先选有阻塞项的文件，没有阻塞项时会回退到有警告的文件，因此页面不能固定命名为“阻塞文件”。空列表显示“暂无优先复核文件”。

### 6.2 发现卡与检索

补充 `category`、`rule_version`、`count`。当 `count > 1` 时显示“同规则在此文件聚合命中 N 次”。`summary` 的数量表示聚合后的发现条数，不能与命中次数总和混用。

聚合发现只保留一段证据，起止行覆盖合并后的范围；没有逐次命中列表。不要把这个范围渲染为连续每行都命中，也不要承诺点击次数可以展开全部匹配代码。

P1 增加按分类、规则、文件筛选，以及针对标题、规则 ID、路径、消息的文本搜索。所有筛选可组合、可清除，展示“当前结果数 / 全部发现数”；保留现有严重级别筛选的可访问性和键盘操作。

### 6.3 报告元数据

新增“报告详情”折叠区：

| 字段 | 展示要求 |
| --- | --- |
| `scan_id`、`schema_version` | 完整值；扫描 ID 可复制，用于打开报告和 MCP 查询 |
| `repository.commit` | 完整 40 位提交可见、可复制；保留仓库外链 |
| `ruleset_digest` | 完整 SHA-256，可复制；旧报告为 null 时显示“未记录” |
| `extra_ruleset_version` | 有值显示，无值显示“无扩展规则版本记录” |
| `analysis_config` | 展示后端实际记录的参数；旧报告为空时显示“未记录分析配置” |
| `analysis_config.prefilter` | 保留 `on`/`off`/`unavailable` 的区别；技术解释置于详情中 |

元数据是对已生成报告的说明，不添加让用户在报告页修改扫描器配置的假设置项。

### 6.4 迁移清单

保留现有动作和受影响文件，补充 `rule_id`、关联发现入口及 `completed` 的只读状态。文件较多时可折叠，不能截断后无法查看。

后端当前生成清单时默认 `completed=false`，没有完成状态更新接口。基础版只读展示，不加可勾选且声称已保存的复选框；完成状态也不能改变静态或真机结论。

依据：[模型与汇总逻辑](../src/mxready/models.py)、[聚合和清单生成](../src/mxready/scanning/analyzer.py)、[路径上下文](../src/mxready/scanning/path_context.py)、[规则说明](rules.md)。

## 7. 验证、任务与其他能力（FE-05、FE-07～FE-09）

### 7.1 真机验证说明

验证区已有上传下载，本轮补充操作说明和结论范围：

- `inspect`：只运行清单中的固定环境检查，不运行项目命令。
- `run`：用于已人工补充 `project_commands` 的清单；项目命令必须经过审阅，并在 runner 中精确输入 `yes` 才执行。
- 默认下载包的 `project_commands` 为空，`project-commands.example.json` 只是模板，用户需要按项目实际情况修改。
- “已验证”代表上传结果满足后端校验，绑定同一提交且未过期；不能写成完整项目功能、性能或迁移认证。

两种命令都提供可复制文本，但网页不运行 runner。继续保留上传前脱敏检查、1 MiB 上限、JSON 请求体、错误码、上传中禁用和成功后更新报告。

当前 API 只返回 `verification_status`，无法据此判断某次验证究竟执行了哪些项目命令，也无法展示实际验证时间、设备详情或失败日志；这些属于后续接口扩展。

### 7.2 打开任务、分享与重新扫描

新增“打开已有扫描”输入框，校验 UUID 后复用当前恢复逻辑；报告页提供“复制报告链接”和“同仓库重新扫描”，后者预填仓库与完整提交，由用户显式提交新任务。

进度/任务详情补充 `id`、`requested_ref`、`resolved_commit`、`created_at`、`updated_at`；尚未解析提交时明确显示等待解析。失败页保留任务身份和错误码，支持复制诊断信息。

读取失败后的“继续查看”仍是重新读取原任务；`SCAN_INTERRUPTED` 应提示创建新扫描，不能写成“恢复执行”或“自动重放”。离开页面、导航切换和中止浏览器请求均不代表取消后端任务。

新增规则库/MCP 导航时要保留扫描状态。可使用 `?page=rules`、`?page=mcp` 与现有 `?scan=` 组合，返回源码体检后继续查看原任务；导航不得隐式重新提交扫描，也不能无意清除原扫描 ID。

### 7.3 服务、刷新与徽章

使用 `GET /api/health` 展示当前 Web 服务版本与请求状态，和历史报告记录的 `tool_version` 分开。加载失败可以重试，不阻止新建体检页面使用，也不充当 MCP 健康检测。

报告页增加“刷新报告”按钮，重新调用 `getReport`，获得后端按当前时间推导的验证状态。前端不根据静态扫描时间计算验证到期时间。

徽章工具补充 SVG 预览、复制图片地址和 Markdown 嵌入代码。地址使用当前部署的真实来源和扫描 ID；提示外部 README 展示要求该地址可被访问，本机 `localhost` 地址不能用于公开展示。通过图片元素展示现有 SVG，不把响应注入为 HTML。

### 7.4 命令行使用说明

提供本地目录扫描和批量评估的介绍、现有 README 中的实际命令，并明确：

- Web 输入仍是单个公开仓库 URL；本地目录由 `mxready-scan` 在用户主机读取。
- 多个公开仓库由 `mxready-scan-batch` 处理，输出逐仓报告和批量汇总。
- CLI 写出的本地报告文件不会仅因存在于磁盘而自动出现在 Web 数据库中。
- 这里提供使用说明和复制操作，不提供源码 ZIP 上传、读取浏览器本地目录或 Web 批量执行的虚假入口。

依据：[runner 指南](runner.md)、[验证包生成](../src/mxready/verification/bundle.py)、[扫描服务](../src/mxready/services/scans.py)、[服务健康接口](../src/mxready/app.py)、[本地扫描 CLI](../src/mxready/cli/scan_repository.py)、[批量 CLI](../src/mxready/cli/scan_batch.py)。

## 8. 需要后端扩展的能力

以下能力有使用价值，但当前不能作为“后端已提供接口、前端只是没显示”来实施：

| 能力 | 当前实际情况 | 若实施需增加什么 |
| --- | --- | --- |
| 服务端扫描历史、分页、跨设备列表 | 已有按 ID 的查询，没有扫描列表接口 | 带分页/筛选的任务列表 API；明确部署范围与数据访问边界 |
| 真机验证详情、实际时间和剩余有效期 | 内部保存 `VerificationRun`，但公开报告只返回状态 | 最新验证结果查询或摘要契约；有效期由后端提供依据；输出继续遵守脱敏与上限 |
| 多次验证历史 | 当前 `verification_json` 保存最新一次，后续上传覆盖该字段 | 独立历史记录存储、迁移和列表契约，不能从当前字段还原历史 |
| 勾选并保存迁移清单 | 有 `completed` 字段，没有更新接口 | 写入契约及持久化；明确它只是人工记录，不是扫描结果 |
| MCP 安装/连接检测 | 没有公开探测接口，stdio 客户端位于其他进程 | 明确检测对象的能力信息 API；Web 依赖检测不能冒充客户端握手结果 |
| 网页批量扫描、取消任务、远程执行 MCP | 现有 HTTP 路由不支持这些工作流 | 分别设计准入、任务状态、访问控制及协议边界，不能用前端按钮替代 |

本轮不引入私有仓库、账号系统、自动修改源码、云 GPU 调度或百分比兼容分数。Web 服务继续只做静态分析，runner 保持用户主机执行、命令白名单、`shell=False`、人工确认、超时、脱敏和输出限制。

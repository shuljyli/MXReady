## 3. F1：报告搜索与筛选

### 3.1 命令契约

保留 `/findings 2` 的旧用法，新增：

```text
/findings [页码] [--severity blocker|warning|info|all]
          [--rule MXR-WARP-001] [--file 路径片段] [--query 关键词] [--reset]

/findings --severity blocker
/findings --file "csrc/" --query "warp"
/findings 2
/findings --reset
```

具体语义：

- 同一次命令的不同条件使用 AND；关键词在标题、规则 ID、路径、主证据、逐次证据、
  问题说明和整改建议之间使用 OR。
- `--rule` 精确匹配规则 ID，输入去除首尾空白并转大写；未知规则返回零结果，不触发规则下载。
- `--file` 为字面量子串，不支持正则或 glob。仅在匹配副本中将 `\\` 统一为 `/`，不改写报告路径。
- 文本搜索使用 Unicode `casefold()`，文件筛选也采用不区分大小写的搜索体验；
  这不改变第 5 节中用于报告对比的大小写敏感路径身份。
- `--severity all` 清除级别条件；`--rule ""`、`--file ""`、`--query ""` 清除各自条件。
  未提供的条件沿用当前报告状态。
- 任一条件变化时默认回到第 1 页；同时指定页码时，页码作用于新的筛选结果。
  无参数 `/findings` 展示当前页，首次打开默认第 1 页；这项体验调整需写入更新记录。
- `--reset` 清空全部条件并回到第 1 页；与其他筛选参数或页码混用时报参数错误，保持旧状态。
- 页码必须为正整数，显式越界提示有效范围并保留原状态。恢复的旧页码越界时收敛到最后一页。
- 文件条件最多 4096 字符、规则 ID 最多 100 字符、关键词最多 256 字符；保留整条命令
  8192 字符上限。所有参数校验通过后才提交状态。

### 3.2 数据与展示

新增内部类型：

```python
@dataclass(frozen=True)
class FindingFilter:
    severity: Severity | None = None
    rule_id: str = ""
    file_query: str = ""
    text_query: str = ""

@dataclass(frozen=True)
class FindingPage:
    indices: tuple[int, ...]  # 原始报告中的索引，仅保存当前页
    matched_total: int
    report_total: int
    page: int
    page_count: int
```

分页按聚合 finding 计数，`finding.count` 是该组的命中次数；两者不能混用。
沿用报告原始顺序和每页 5 项，不因筛选重新排序。空结果展示“匹配 0 / 全部 N 项”，
内部页码保持 1、页数保持 1，不显示下一页。

标题始终显示活动条件、匹配总数、原报告发现数与当前页。原报告摘要不随筛选变化。
查询要检查完整证据文本，显示时继续截断长证据；不能用截断后的文本做匹配。
旧报告没有 occurrences 时回退到主证据。

筛选是纯函数，不修改 `report.findings`，不改变导出、基线或清单。
首次可直接线性遍历，不复制整份报告；重复翻页复用匹配索引。
缓存键为当前文件内容摘要与筛选值，切换报告或内容变化即失效，最多保留当前查询缓存。
大报告筛选放入后台工作，取消后通过 generation 拒绝迟到更新；不承诺线程可被强制终止。

## 4. F2：历史恢复与报告选择器

### 4.1 入口与恢复行为

新增 `/reports [--query 关键词] [--batch 批次ID]`，打开可搜索的报告选择器。
默认只列当前启动项目关联的记录；`--all-projects` 显式查看同一状态库的其他项目。
此选项仅扩展列表范围，不切换 `/scan` 的默认目录和相对路径基准。

选择器展示仓库、提交前缀、扫描时间、静态计数、来源类型、文件可用性和批次状态。
列表每页 20 条，按最近访问时间降序、记录 ID 次序稳定排序；扫描时间单独显示，不混同访问时间。
Enter 打开，Esc 关闭并返回原输入焦点。选择必须绑定内部记录 ID，不能依赖排序后的行号。
缺失或无效文件仍列出原因，但不能作为正常报告打开。

启动只恢复历史、项目关联和轻量列表，不自动扫描、不执行历史命令、不自动读取上次报告正文。
`/report` 在没有当前报告时尝试打开该项目最近一次成功访问的记录；无效时提示使用 `/reports`。
显式 `/report <路径>` 读取成功后登记；恢复筛选状态时必须同时匹配 scan ID 与文件内容摘要。
文件内容变化则清空其浏览状态，使用新内容重新建立索引。

启动项目仍由显式参数或当前目录决定。状态库记住“最近项目”用于列表筛选和提示，
不在重启时悄悄改变用户所在目录。显式 `--output-dir` 保持最高优先级，
否则恢复当前项目上次通过 `/output` 设置的目录，再回退到用户数据目录下的 `reports`。
恢复目录时不自动创建它；真正输出前再检查并处理错误。

### 4.2 状态存储

使用标准库 SQLite，路径为 `<MXREADY_DATA_DIR 或默认用户数据目录>/tui/state.db`。
与扫描报告目录及 Web 服务数据库分离，`--output-dir` 不改变状态库位置。
新增启动参数 `--no-state`：本次会话不读取或写入状态库，历史与报告目录只保存在内存中。

采用独立 schema 版本和事务迁移；第一版建议包含以下逻辑表：

| 表 | 主键 / 唯一键 | 关键字段与用途 |
| --- | --- | --- |
| `projects` | `project_key` | 规范化绝对目录、最近访问时间、输出目录、最近报告记录 ID |
| `command_history` | 自增 ID | project_key、结构化命令 JSON、创建时间 |
| `report_entries` | 自增 ID；`(project_key, canonical_path)` 唯一 | scan_id、文件摘要、仓库、提交、扫描时间、摘要计数、来源、最近访问时间 |
| `report_views` | 报告记录 ID | 对应内容摘要、筛选 JSON、页码 |
| `batches` | `batch_id` | project_key、输出目录、结束时间、进程退出码、完成/失败/取消状态 |
| `batch_items` | `(batch_id, ordinal)` | 仓库/ref、执行结果、错误摘要、可选报告记录 ID |

项目键基于解析后的绝对路径；Windows 使用 `normcase`，其他平台保留大小写。
路径标识用于本机恢复，不作为仓库身份或可信来源证明。
外键约束启用；删除目录索引只影响状态库，不能删除报告文件或 Web 记录。
批次条目指向的报告记录被淘汰时设为 null，不能把原先成功扫描改写成执行失败。

每次操作使用独立连接，设置 1 秒锁等待上限；写操作为短事务，事务内不读取报告文件。
多个 TUI 实例通过唯一键和 upsert 合并目录记录；筛选、最近报告与输出偏好采用最后提交写入者生效，
不整库覆盖。启动及退出禁止持有跨文件 I/O 的数据库事务。

建议默认上限：每项目 200 条命令、100 个项目、全库 2000 个报告记录、200 个批次、
每批最多 1000 个条目。超限按最近访问时间淘汰状态记录，扫描文件不动；
超大批次显示条目已截断及完整汇总位置。上述上限为新设计常量，应集中定义并测试。

状态库不存在则创建；只读、损坏、锁超时或 schema 比当前实现更新时，显示一次原因并降级为
本次会话内存模式，不覆盖、不删除原库，不阻断扫描。首次运行与 `--no-state` 都必须可用。
退出不等待无界状态写入；已完成操作及时提交，退出只等待有界的收尾写入。

### 4.3 历史内容与隐私

仅持久化解析、语义校验成功且已接受的命令；保留当前会话中失败命令的上下键编辑体验，
但不把任意原始输入写入磁盘。存储类型化参数，恢复时由统一 formatter 安全生成输入文本，
随后仍通过同一解析器，禁止 `eval` 或 shell 执行。

URL 含用户信息、查询参数或片段时不持久化该命令；不保存子进程输出、报告正文、环境变量、
令牌或验证日志。已接受的本机路径会留在用户状态库中，应在 CLI 文档明确说明。
相邻完全相同命令去重；恢复只填充历史，不自动执行。
formatter 必须对引号、空格、反斜杠与 Unicode 做解析往返测试；无法无损表达的条目跳过并提示。
`/clear` 保持只清屏语义，不兼作删除历史。

### 4.4 报告登记与批量结果

报告来源限于：用户显式打开的 JSON、本次任务新建输出目录及已有状态索引。
不在启动时递归遍历用户目录。报告列表默认显示缓存摘要，打开时重新进行大小限制、模型校验
和摘要计算；缓存不是报告真值。列表中的来源和计数应标为“上次读取”，不要据缓存生成新结论。

单次扫描结束后仅枚举本次输出目录顶层 JSON，逐个校验，隔离无效文件；扫描失败或取消后
已经完成的有效报告仍可登记，批次整体状态与条目报告状态分别显示。
读取多文件时逐个处理并在文件之间检查取消，不同时加载全部报告正文。

首版复用现有 `batch-summary.csv`，不增加扫描 CLI 的外部输出格式：

1. 有界读取 CSV（建议 2 MiB），核对现有字段 `repository/ref/commit/status/report/error`，
   保留原始行序。成功状态为静态报告状态，`blocked` 不是执行失败。
2. CSV 的 `report` 当前指向 Markdown，不是 JSON；只将 `.md` 后缀替换为 `.json` 寻找同组报告。
   结果必须是本次输出目录的直接子文件；拒绝绝对路径、目录分隔符、盘符、`..` 和符号链接逃逸。
3. 校验 JSON 中的仓库与提交和 CSV 一致。摘要计数及静态状态以校验后的 JSON 为准；
   不一致时标记汇总不一致，不能静默显示可信匹配。
4. `failed` 条目只展示有界、转义后的错误；没有报告路径时不尝试推测文件。
5. CSV 缺失、损坏或超限时，展示“批次汇总不可用”，仅列当前目录内已校验的报告，
   未知失败数量保持未知；不能从报告数反推总任务数或宣称全部完成。

批量结束打开结果列表，不再自动选择字典序最后一份；只有用户选择才替换当前报告。
单仓扫描成功仍自动打开本次结果，保留原有体验。

## 5. F3：TUI 报告对比

### 5.1 命令与界面

```text
/compare <基线JSON路径> [当前JSON路径]
/compare
```

给定一个路径时，以当前已打开报告为“当前”；无当前报告则提示先打开报告。
给定两个路径时分别有界读取，不改变主界面当前报告。
无参数时打开基线选择器，以当前报告仓库过滤候选，排除相同 scan ID；仍可用路径显式打开。
历史路径不存在时不自动新建扫描。

比较结果使用独立弹层，提供“新增、消失、保留、级别变化、次数变化”五组，默认新增，
每页 5 项。展示两侧 scan ID、提交、扫描时间、来源和分析条件差异。
Esc 退出对比并恢复主报告、筛选、页码与输入焦点；不把对比结果持久化为扫描报告。

### 5.2 Python 对比接口

在 `reporting/comparison.py` 新增纯函数 `compare_reports(baseline, current)`，返回内部
dataclass `ReportDifference`；不加入公共 API 模型，不新增 HTTP 路由。
结果至少包含：

- `added`、`removed`、`retained`：对应 finding 引用。
- `changes`：成对的 `before` / `after`，分别记录级别和次数是否变化。
- `condition_differences`：工具版本、规则摘要/版本、扩展版本、分析配置的两侧值。
- `conditions_status`：`same` / `different` / `unknown`。
- `source_warnings`：来源缺失、工作区或声明目录提示，与分析条件分开。

匹配键严格为 `(rule_id, relative_path)`，路径保留原大小写，不用行号或证据文本做身份。
新增、保留和变更项沿用当前报告顺序；消失项沿用基线顺序。
相同行号移动不计新增；同键严重级别或次数变化形成变更记录。
级别与次数变化可以重叠，不相加成“总问题数”；严重级别按 info < warning < blocker 比较。
若报告内出现重复匹配键，应报结构歧义，不能通过字典覆盖静默丢失发现。

仓库 URL 规范化沿用 CI 当前的去尾斜杠、去 `.git`、转小写约定，不在本轮加入 SSH 或
跨提供方仓库等价推断。同仓库不同提交或不同 input_digest 允许比较，这是整改对比的正常输入。
不同仓库必须拒绝。相同 scan ID 且内容不同应拒绝并提示身份冲突；相同报告可显示零差异。

### 5.3 浏览比较与 CI 的边界

| 情况 | TUI 浏览比较 | CI `new_blockers()` |
| --- | --- | --- |
| 仓库不一致 | 拒绝 | 保持拒绝 |
| 已知分析条件一致 | 展示差异 | 保持现有严格判断 |
| 任一已知分析条件不同 | 展示差异及具体差异警示 | 保持拒绝 |
| 缺规则摘要，其他条件无已知变化 | `unknown`，提示无法确认条件一致 | 保持拒绝 |
| 来源未知 / 工作区来源 | 明示来源范围，不能称为已验证整改 | 不在本轮额外改变既有来源策略 |

`analysis_config` 按映射值语义比较，不依赖序列化键顺序。若既有条件差异又缺摘要，
状态为 `different`，同时保留缺摘要警示。来源差异不自动等同于分析条件变化。
“消失”不称为“已修复”；文件排除、规则变化和扫描范围变化都可能影响结果。
有 coverage 时并排展示文件数与跳过统计，但不把数量相等视为范围相同证明。

保留现有 `new_blockers()` 签名、错误条件与返回规则；不得为了 TUI 允许跨条件浏览而放宽它。
可提取共享键生成和仓库规范化 helper，但 CI 路径不直接依赖宽松的 UI 判断。
为 Python 与已有 TypeScript 比较建立共享语义夹具，覆盖键、计数、级别和条件差异；
无需强制把 Web 逻辑搬到服务端。新行为涉及 Web 时单独更新其回归。

## 6. F4：TUI / Web 完整展示来源

### 6.1 展示规则

复用现有 `ScanSource`，不新增 ScanReport 字段、不修改 schema_version。

| 输入 | 主标签 | 必须展示的说明 |
| --- | --- | --- |
| `git-commit` | 干净 Git 提交 | 报告记录的实际 HEAD；不宣称签名、完整仓库或构建来源认证 |
| `working-tree` | 工作区快照 | HEAD 不包含未提交修改；扫描对象是当时纳入分析的内容 |
| `declared-directory` | 显式声明目录 | 仓库/提交由调用者声明，Git 来源未核对 |
| source 缺失或 null | 未记录来源元数据 | 可能是旧报告或未采集该字段的扫描路径，不推断为干净提交 |

字段包括 `repository.commit`（报告关联/声明的提交）、`actual_commit`（探测到的 HEAD）、
`dirty`（true/false/null 显示有修改/无修改/未知）和 `input_digest`（已索引文件集合摘要）。
摘要缺失显示“未记录”，不用空字符串、零值或当前本机计算结果补齐。
完整 SHA 和摘要支持 Web 复制；TUI 在详情中可完整查看，长行允许换行。

来源字段是报告记录，不在打开报告时重新调用 Git 来替换历史内容。
若 `git-commit` 与 dirty=true、HEAD 与关联提交不一致等信息矛盾，显示“来源记录不一致”，
不得展示“已核对干净提交”的正向结论，也不自动修改文件。缺少关键值时标注记录不完整。
工作区或声明目录的 input_digest 相同，只说明纳入分析的文件集合相同，不代表硬件运行相同。

### 6.2 接入位置

- TUI：`_open_report()` 的摘要中加入来源主标签；详情区输出上述字段。报告选择器缓存来源标签，
  对比弹层同时展示两侧来源。保留独立的“硬件状态（导出时快照）”文案。
- Web：新增 `ReportSource` 并接入 `ReportDetails`，不因未展开详情而影响现有静态/验证状态。
  `source` 使用缺失兼容判断，即使运行时旧 JSON 不含该键也能渲染。
- Web 源码链接：`working-tree` 的远程提交内容可能与命中行不同，链接文案改为
  “查看关联提交（可能与工作区不同）”；`declared-directory` 标明“声明提交（未核对来源）”；
  来源未知保留固定提交链接但注明来源未记录。此处只调整语义和 props，不新增本地文件访问接口。
- Python 来源展示 helper 与 Web 组件共享测试用例语义；不为共享几段文案引入运行时跨语言依赖。

保持 Markdown / HTML / SARIF / JSON 的现有来源信息与旧报告读取能力。
本次展示不补算验证 freshness，离线 JSON 没有验证执行时间，不能据 scanned_at 推导硬件有效期。

## 7. 交互、性能与错误处理

- 新增选择器和对比弹层保留独立 Esc 处理；主界面的 Escape 不设抢占优先级。
  输入框 ↑↓ 历史与列表 ↑↓ 导航按焦点分派，不能同时触发。
- 扫描运行中允许对已加载报告筛选；首版禁止打开另一份报告、启动对比或更换输出目录，
  沿用单任务约束并给出明确提示，避免扫描完成后覆盖用户刚打开的报告。
- `/cancel` 与 Ctrl+C 保留任务取消语义；弹层关闭只取消视图请求，不取消其他扫描。
  Ctrl+Q 仍先执行原有进程树清理，再结束应用。
- 保留终端输出容量与日志队列上限。列表分页渲染，不一次输出全部报告或全部差异。
  报告解析、目录校验和数据库 I/O 放到后台；选择器每次只校验用户打开的文件。
- 来自报告、CSV、历史、路径和错误消息的文本全部经过 `safe_text` 或等价转义，
  Rich markup 不解释为控制指令；Web 文本通过 React 转义，不使用原始 HTML。
- 新增错误应区分：参数无效、报告过大、JSON/模型无效、路径不可读、批次汇总不可用、
  仓库不一致、重复发现键、来源不完整、状态库不可用。失败不清空当前有效报告。

性能验收使用固定合成报告：1 万个 findings、合计不超过现有 20 MiB 上限，以及 2000 条目录记录。
记录机器、Python、Textual 版本、冷/热读取时间、筛选和翻页耗时及峰值内存。
初步目标为热筛选 500 ms 内、缓存翻页 100 ms 内；这些是待测目标，不是已取得的结果，
不作为跨平台 CI 的脆弱墙钟断言。必须通过行为测试验证后台工作期间按键和取消可处理。
